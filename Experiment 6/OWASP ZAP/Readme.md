
# Experiment 6: Website Risk Assessment Using OWASP ZAP

## Aim
To assess the security of a website using OWASP ZAP, identify potential web application vulnerabilities, and recommend suitable security measures.

## Overview
OWASP ZAP (Zed Attack Proxy) is an open-source web application security testing tool. It helps identify security weaknesses by analyzing HTTP requests and responses and scanning web applications for potential vulnerabilities.

## Tools and Technologies
- **OWASP ZAP** – Web application security testing
- **Web Browser** – Accessing the target website
- **Target Website** – A website authorized for security testing

## Methodology
1. Install and launch OWASP ZAP.
2. Configure the browser to access the target website through ZAP, if required.
3. Enter the authorized target website URL.
4. Browse the website to allow ZAP to observe requests and responses.
5. Run an appropriate passive or active scan, depending on authorization and lab requirements.
6. Review the alerts generated by OWASP ZAP.
7. Analyze the risk levels and evidence associated with the findings.
8. Recommend remediation measures for the identified security issues.

## Key Observations
- Observed website traffic through OWASP ZAP.
- Examined security alerts generated during scanning.
- Learned how to interpret vulnerability severity and supporting evidence.
- Understood the importance of validating findings before treating them as confirmed vulnerabilities.

## Security Recommendations
- Use HTTPS and secure communication settings.
- Configure appropriate security headers.
- Validate user input and handle errors securely.
- Apply software updates and security patches.
- Re-test the website after implementing remediation measures.

## Result
Website risk assessment was performed using OWASP ZAP to understand web application security testing and the identification of potential vulnerabilities.

## Learning Outcomes
- Understanding the working of OWASP ZAP.
- Learning the basics of website security assessment.
- Interpreting vulnerability alerts and risk levels.
- Understanding remediation and security verification.

## Disclaimer
Perform security testing only on websites you own or have explicit permission to assess. Active scans may affect website functionality, so use an authorized test environment.
