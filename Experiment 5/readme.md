
# Network Security Lab: Observing an HTTP Session (Experiment 5)

##  Overview

This experiment demonstrates the security risks of unencrypted HTTP communication on a shared local network. Using an isolated virtual lab with Kali Linux and Metasploitable 2, ARP spoofing was observed in a controlled environment, and Wireshark was used to analyze HTTP traffic generated by the Damn Vulnerable Web Application (DVWA).

##  Objectives

- Understand the security risks of unencrypted HTTP traffic.
- Observe ARP spoofing in an authorized virtual lab.
- Enable IP forwarding to support packet forwarding.
- Capture and analyze network traffic using Wireshark.
- Identify an HTTP POST request and understand the importance of HTTPS.

##  Methodology

### 1. Verify Network Connectivity
Ping tests were performed from Kali Linux to verify connectivity with the target machine and gateway.

### 2. Enable IP Forwarding
IP forwarding was enabled on Kali Linux to allow packets to pass through the system during the controlled lab exercise.

### 3. Observe ARP Spoofing
ARP replies were used in the isolated lab to demonstrate how incorrect IP-to-MAC address mappings can redirect network traffic through an intermediary system.

### 4. Capture Traffic Using Wireshark
Wireshark was used to capture and inspect packets involving the target machine. Network connectivity was verified while the capture was running.

### 5. Analyze the HTTP Session
The capture showed an HTTP `POST /dvwa/login.php` request. The DVWA page displayed after authentication confirmed that the test login session was successful.

##  Results and Findings

- The target and gateway were reachable before traffic inspection.
- IP forwarding was enabled on Kali Linux.
- ARP spoofing was demonstrated in the isolated virtual lab.
- Wireshark captured packets involving the target.
- An HTTP POST request to the DVWA login endpoint was observed.
- The experiment demonstrated that HTTP does not encrypt application data in transit.

##  Security Recommendations

- Use HTTPS with valid TLS certificates to encrypt web communication.
- Configure session cookies with `Secure`, `HttpOnly`, and appropriate `SameSite` attributes.
- Use network protections such as Dynamic ARP Inspection where supported.
- Avoid transmitting sensitive information over unencrypted HTTP.
- Monitor network traffic for suspicious ARP changes and unexpected packet forwarding.

##  Ethical and Safety Notice

This project is intended strictly for educational purposes in an isolated virtual lab using systems you own or are explicitly authorized to test.

Never perform ARP spoofing, traffic interception, or credential collection on public, shared, or production networks without explicit authorization.
