# Experiment 5: Sniffing and Session Hijacking

## Overview

This experiment demonstrates how network traffic can be intercepted and analyzed in an isolated virtual lab environment using Kali Linux, Metasploitable 2, and Wireshark. It focuses on ARP spoofing, Man-in-the-Middle (MITM) attacks, packet capturing, and the security risks associated with unencrypted HTTP communication.

The experiment helps understand how sensitive information, such as login credentials and session data, can potentially be exposed when HTTP is used instead of HTTPS.

## Objective

To understand how ARP spoofing and packet sniffing can be used to observe unencrypted HTTP login traffic and identify session security risks in a controlled virtual lab environment.

## Lab Environment

- **Kali Linux:** Analysis and testing machine.
- **Metasploitable 2:** Target machine running DVWA.
- **DVWA:** Vulnerable web application used for HTTP login testing.
- **Wireshark:** Network packet capture and analysis tool.
- **Network Interface:** eth0.
- **Target IP:** 192.168.1.100.
- **Gateway IP:** 192.168.1.1.
- **Network Configuration:** Isolated virtual lab network.

## Tools Used

- Kali Linux
- Metasploitable 2
- DVWA (Damn Vulnerable Web Application)
- Wireshark
- ARP spoofing tool
- VMware / VirtualBox

## Methodology

### Step 1: Configure the Lab Environment

Set up Kali Linux and Metasploitable 2 as virtual machines. Configure both machines on an isolated virtual network and ensure DVWA is running on the target machine.

### Step 2: Verify Network Connectivity

Check the IP addresses of the virtual machines and verify communication between Kali Linux, the target machine, and the gateway.

### Step 3: Enable IP Forwarding

Enable IPv4 packet forwarding on Kali Linux to allow network traffic to pass through the analysis machine during the controlled MITM demonstration.

### Step 4: Perform ARP Spoofing

Demonstrate ARP spoofing between the target machine and the gateway. This causes the communicating machines to associate the attacker's MAC address with the other device's IP address.

### Step 5: Verify Traffic Forwarding

Check that IP forwarding is enabled and observe the network traffic passing through Kali Linux.

### Step 6: Capture Network Traffic

Launch Wireshark on the eth0 interface and capture traffic generated by the target machine while accessing DVWA.

### Step 7: Analyze HTTP Login Traffic

Generate a login request from DVWA and inspect the captured HTTP packets. Observe the HTTP POST request and understand how unencrypted communication can expose sensitive information.

### Step 8: Verify the DVWA Session

Confirm that the DVWA browser session is authenticated and understand the relationship between HTTP requests, login authentication, and session management.

## Key Observations

- Kali Linux successfully communicated with the target machine and gateway.
- ARP spoofing demonstrated how local network traffic can be redirected.
- IP forwarding allowed traffic to continue passing through Kali Linux.
- Wireshark captured network packets involving the target machine.
- An HTTP POST request was observed during DVWA login.
- The experiment demonstrated the risk of transmitting sensitive information over unencrypted HTTP.
- Authenticated web sessions highlighted the importance of secure session management.

## Result

The experiment demonstrated how ARP spoofing can redirect local network traffic through Kali Linux when packet forwarding is enabled. Wireshark was used to capture and analyze DVWA HTTP login traffic, showing the security risks of transmitting sensitive information without encryption.

## Conclusion

This experiment provided practical knowledge of network sniffing, ARP spoofing, Man-in-the-Middle attacks, and session security. It demonstrated that unencrypted HTTP communication can expose sensitive information to network observers. The experiment also highlighted the importance of HTTPS, secure cookies, and proper network security configurations.

## Security Recommendations

1. **Use HTTPS:** Encrypt communication between browsers and web servers using TLS.
2. **Enable Secure Cookies:** Use Secure, HttpOnly, and SameSite cookie attributes.
3. **Use Network Segmentation:** Separate sensitive systems from untrusted devices.
4. **Enable ARP Protection:** Use Dynamic ARP Inspection and other suitable network protections.
5. **Monitor Network Traffic:** Use Wireshark and IDS tools to identify suspicious network activity.
6. **Use Secure Session Management:** Regenerate session IDs after authentication and apply proper session expiration.



This experiment was performed in an isolated virtual lab using Kali Linux and Metasploitable 2 with DVWA. ARP spoofing, traffic interception, and packet capture should only be performed on systems and networks for which explicit authorization has been obtained. Disposable test accounts should be used during security testing.
